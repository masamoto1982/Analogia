# Analogia 設計メモ

Analogia は、MONIAC（フィリップス機）のような**流体式アナログコンピュータ**を
テキストで組み立てて動かすための言語です。プログラムは「計算の手順」ではなく
「配管図」を書きます。タンクに量が貯まり、パイプがそれを流し、`RUN` で
連続時間のまま時間を進めると、水位が自然に釣り合う点を探していきます。

## 1. 発想の元

| アナログ計算機 | MONIAC | Analogia |
|---|---|---|
| 積分器（コンデンサ） | 水槽 | `TANK`（ストック） |
| 電流・信号線 | 配管を流れる水 | `PIPE`（フロー） |
| 係数器（ポテンショメータ） | バルブの開度 | レートブロック `[ X 0.3 MUL ]` |
| 関数発生器 | 形を切り出したカム板 | `CAM`（区分線形の曲線） |
| 演算の実行 | ポンプを回す | `RUN`（連続時間シミュレーション） |
| 初期条件のリセット | 水を入れ直す | `REWIND` |

中心の性質は **保存則** です。パイプはあるタンクから別のタンクへ量を「移す」
だけなので、外界（`OUTSIDE`）につながるパイプがない限り、全タンクの合計は
変わりません。`RUN` の出力はその合計を毎回表示します。MONIAC で水が見せてくれた
「お金は消えずに循環する」という性質を、言語の構造そのものが保証します。

もう一つの物理的な性質として、**空のタンクからは流れません**。流量の計算結果が
正でも、流出元が空ならそのパイプは 0 を運びます（負の流量は逆向きの流れで、
そのときは流入先側が空かどうかを見ます）。

## 2. 構文

テンプレート由来の後置記法（スタック言語）をそのまま使います。値を積み、
ワードがそれを消費します。`[ ... ]` は実行されないブロックで、パイプの流量式や
ユーザーワードの本体になります。

```
100 'BATH' TANK                                  # 水位 100 のタンク
[ 5 ] 'OUTSIDE' 'BATH' 'TAP' PIPE                # 外から毎時 5 流れ込む蛇口
[ BATH 0.1 MUL ] 'BATH' 'OUTSIDE' 'DRAIN' PIPE   # 水位の 1 割が流れ出る排水口
30 0.1 RUN                                       # 30 時間、刻み 0.1 で流す
```

- `水位 '名前' TANK` — タンクを宣言する。同じ名前でもう一度書くと水位を入れ直す。
- `[ 流量 ] '流出元' '流入先' '名前' PIPE` — パイプをつなぐ。`'OUTSIDE'` は外界。
  同じ名前でもう一度書くと付け替える（スクリプトを何度実行しても配管が増えない）。
- `期間 刻み RUN` — 4 次のルンゲ＝クッタ法で積分し、各タンクの推移を
  スパークラインで、各パイプの最終流量と全体の水量を表で出す。
  時計は続きから進むので、`RUN` を重ねると「流しながら政策を変える」実験ができる。
- `REWIND` — 全タンクを宣言時の水位に戻し、時計を 0 にする。

レートブロックの中では、

- タンク名はその時点の**水位**、
- パイプ名はその時点の**流量**（他のパイプの流れに比例するバルブが書ける。
  自分自身に依存すると循環としてエラー）、
- `TIME` は時計、
- `x [ x0 y0 x1 y1 ... ] CAM` はカム板（区分線形補間、両端は一定）

を読めます。ブロックは数値をちょうど 1 つ残す必要があり、`TANK`・`PIPE`・
`RUN`・`DEF`・`PRINT` などの「機械を組み替える・出力する」ワードは使えません。

算術は `ADD SUB MUL DIV MIN MAX`、比較は `EQ LT GT`、選択は
`条件 a b IF`（条件が真なら a、偽なら b）、スタック操作は `DUP DROP SWAP`。
`DEF` で定義したユーザーワードは政策パラメータ（`[ 0.25 ] 'TAX-RATE' DEF`）や
共通の式に使い、Dictionary パネルに並びます。パイプが使っているワードは
`DEL` できません。

## 3. 実行モデル

1. ソースを左から評価して配管（`Model`：タンク・パイプ・時計）を組み立てる。
2. `RUN` は状態ベクトル（全タンクの水位）に対して RK4 を回す。各段で
   全パイプの流量を一度ずつ評価し（メモ化。パイプ同士の参照もここで解決）、
   流出元から引いて流入先に足した値が各タンクの変化率になる。
3. 失敗した実行は、スタック・辞書・配管をすべて実行前に戻す。
4. Playground との状態のやり取り（`snapshot_stack`）はスタックと配管を
   まとめて運ぶので、Web Worker で実行しても配管が失われない。

数値は連続量なので `f64` です（テンプレートの正確な分数はやめました）。
Stack エリアでは小数 6 桁までの分数で表示し、丸めた場合は `≈` が付きます。

## 4. 例

`examples/moniac.alg` が MONIAC 風の国民経済モデルです。企業・家計・国庫・
遊休残高・海外の 5 つのタンクを、所得・課税・貯蓄・輸入・消費・政府支出・
輸出・投資の 8 本のパイプでつなぎ、50 期間流したあとに減税して
さらに 50 期間流します。投資は遊休残高をカムに通した割合で決まります
（残高が多いほど金利が下がり投資が増える、という MONIAC の仕掛け）。

## 5. これからの候補

- 配管図の**可視化**（タンクの水位がアニメーションで動く図）。Playground に
  パネルを足す形が自然。
- 遅延（`DELAY`）や、タンクの容量上限とあふれ（`OVERFLOW`）。
- 時系列の取り出し（`RUN` の結果をベクトルとしてスタックに積む）とグラフ表示。
- タンク・パイプの削除と、Dictionary パネルへの表示。
- 内部名の整理（crate 名や TypeScript の型名に残る `ajisai`）。
